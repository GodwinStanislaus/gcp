Google Cloud Hierarchy 🏢

Think of it as a corporate org chart, but with more YAML.

🏛️ Organization (Top company account)
↳ 📁 Folder (Department: Eng, Finance, etc.)
↳ ↳ 📦 Project (Where billing + APIs + resources live)
↳ ↳ ↳ 🌍 Region (Geographic area, e.g., us-central1)
↳ ↳ ↳ 📍 Zone (Specific data center slice, e.g., us-central1-a)
  • Organization: the boss-level umbrella account.
  • Folder: optional grouping for teams and policies.
  • Project: the real working unit for permissions, billing, and services.
  • Region/Zone: where your workloads physically run.

Funny take: Project is your apartment, Region is your city, Zone is your apartment wing.

GKE & Kubernetes Hierarchy 🧱

From cluster to pod: container world in nesting dolls style.

🎛️ GKE Cluster (Managed by Google)
↳ 🖥️ Node Pool (Group of worker VMs)
↳ ↳ 🖥️ Node (One worker machine)
↳ ↳ ↳ 📚 Namespace (Logical room per team/app)
↳ ↳ ↳ ↳ 🚀 Pod (Smallest deployable unit, 1+ containers)
  • Cluster: your whole Kubernetes playground.
  • Namespace: keeps apps from stepping on each other.
  • Pod: tiny house where container(s) live.

Funny take: Pods are lunch boxes; cluster is the school cafeteria.

What is Kubernetes? ❓

A control system that automates container deployment and operations.

What

Kubernetes (K8s) is an orchestration platform for containers.

Why

Handles scaling, self-healing, rolling updates, and service discovery.

How

You declare desired state in YAML, K8s continuously enforces it.

K8s is like a very strict but helpful hostel warden for containers.

How to Use K8s in Real Life 🛠️

Simple workflow students can remember and practice.

  1. Containerize app with Docker.
  2. Create Deployment + Service YAML.
  3. Apply manifests: kubectl apply -f ...
  4. Check Pods/Services: kubectl get pods,svc -n <namespace>
  5. Scale and update with Deployment changes.
Memory trick:

Build → Declare → Apply → Observe → Scale
